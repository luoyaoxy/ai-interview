# RAG 独立服务边界说明

## 1. 决策状态

本项目采纳“RAG 能力独立部署，AI 面试客户端通过 HTTP 调用”的架构方向。

该架构已经完成落地：独立 RAG 服务、HTTP 接口契约和 Qt 客户端接入均已实现。
为便于结果对比和故障回退，旧本地 RAG 源码暂时保留，但默认配置使用独立服务。

## 2. 总体架构

```text
AI 面试项目（C++ / Qt）
    │
    │ HTTP：知识库管理、文档上传、RAG 提问
    ▼
独立 RAG 服务
    ├─ 知识库与文档管理
    ├─ 文档解析与切分
    ├─ Embedding
    ├─ 向量存储与相似度检索
    ├─ RAG Prompt 构建
    ├─ RAG 对话历史管理
    └─ LLM 生成最终答案和引用来源
```

核心原则：默认远程模式下，当前项目不直接访问 RAG 向量库，也不在本地拼接检索
上下文；它只提交业务请求并展示 RAG 服务的结果。只有显式设置
`use_remote_rag=false` 时，才启用保留的本地兼容链路。

## 3. 独立 RAG 服务负责的内容

### 3.1 知识库管理

- 创建、查询、更新和删除知识库。
- 保存知识库名称、描述、角色、文档数量等元数据。
- 决定知识库 ID 的生成规则和有效性。

### 3.2 文档处理

- 接收客户端上传的 PDF、Markdown、TXT、JSON 等知识库文档。
- 校验文件类型、大小和内容。
- 提取文本并按照统一配置进行切分。
- 保存文档、文档块及其来源信息。

### 3.3 向量化与存储

- 调用 Embedding 模型生成文档向量和问题向量。
- 管理 Embedding 模型、向量维度和批处理策略。
- 保存向量及文档块，不向客户端暴露底层 SQLite 或其他向量数据库。

### 3.4 检索与生成

- 根据知识库范围执行相似度检索。
- 应用 Top-K、相似度阈值和过滤规则。
- 构建包含参考资料的 RAG Prompt。
- 调用 RAG 使用的大模型生成最终回答。
- 返回回答、是否命中知识、引用来源及相关度。

### 3.5 RAG 对话状态

- 使用会话 ID 管理 RAG 多轮对话历史。
- 提供清空或结束 RAG 会话的能力。
- 当前项目只保留用于界面展示的聊天记录，不负责把历史重新拼进 Prompt。

### 3.6 服务运行职责

- 提供健康检查、日志、超时、错误码和版本信息。
- 负责 RAG 相关 API 密钥、数据库路径和模型配置。
- 保证文档、向量和知识库元数据的一致性。

## 4. 当前 AI 面试项目保留的内容

### 4.1 Qt 界面

- 保留知识库管理、文件选择、上传进度、提问和来源展示界面。
- 默认远程模式下，界面不直接调用文档解析器、Embedding 或向量数据库。
- 当前已经通过统一的 `RagBackend` 接口和 `RagClient` 调用独立服务。

### 4.2 面试业务

- 保留面试流程、题目推进、语音交互、评分记录和面试报告。
- 保留面试会话状态以及普通对话状态。
- 知识问答模式改为把问题提交给 RAG 服务。

### 4.3 普通 LLM 能力

- 保留根据简历生成问题。
- 保留回答评估、追问决策和面试总结。
- 保留这些功能使用的 `LLMClient`。
- 默认远程模式不再调用 `LLMClient::ChatWithRAG()`；该接口仅供本地兼容后端和
  对比验证使用。

### 4.4 非知识库文档处理

- 候选人简历 PDF 的解析仍属于当前面试项目。
- 因此不能直接删除整个 `PDFParser`；只把“知识库文档解析”职责迁移到 RAG 服务。

### 4.5 通用网络能力

- 保留 `HttpClient`，作为 `LLMClient` 和 `RagClient` 的底层网络模块。
- HTTP 超时、传输错误和通用 Header 继续由 `HttpClient` 处理。
- RAG 请求字段、响应解析和业务错误由 `RagClient` 处理。

## 5. 现有模块的归属决定

| 现有模块 | 默认运行归属 | 处理决定 |
|---|---|---|
| `DocumentLoader` | RAG 服务 | 知识库文件解析与切分已迁移到服务端；C++ 实现仅供本地回退 |
| `EmbeddingClient` | RAG 服务 | 默认由服务端请求 Embedding 模型；C++ 实现仅供本地回退 |
| `VectorStore` | RAG 服务 | 远程知识库和向量由服务端访问；本地数据库只用于兼容验证 |
| `RAGPromptBuilder` | RAG 服务 | 检索、来源组织和 Prompt 构建已迁移到服务端；C++ 实现仅供本地回退 |
| `PDFParser` | 两侧按场景存在 | 知识库 PDF 由服务端解析，简历 PDF 仍由当前项目解析 |
| `LLMClient` | 当前项目保留 | 普通面试功能保留，`ChatWithRAG()` 仅供本地兼容后端使用 |
| `KnowledgeBaseWidget` | 当前项目 | 保留 UI，通过 `RagClient` 管理远程知识库和文档 |
| `KnowledgeChatWidget` | 当前项目 | 保留 UI，通过 `RagClient` 获取答案和来源 |
| `DialogSession` | 当前项目 | 面试状态保留，知识问答分支改为调用 `RagClient` |
| `HttpClient` | 当前项目 | 作为访问 RAG 服务的通用 HTTP 基础模块 |

## 6. 数据所有权

### RAG 服务拥有

- 知识库元数据。
- 上传的知识库文档及其解析状态。
- 文档块、Embedding 向量和索引。
- RAG 对话上下文。
- RAG 使用的模型和检索配置。

### 当前项目拥有

- 当前登录或使用者的界面状态。
- 面试会话、问题、回答、评分和报告。
- 简历原文及其面试用途的解析结果。
- 用于界面展示的 RAG 回答和引用副本。

### 远程模式下明确禁止的共享方式

- 当前项目和 RAG 服务不得同时直接读写同一份 `vectors.db`。
- 当前项目不得依赖 RAG 服务本地文件路径。
- 客户端不得依赖服务端使用 SQLite、FAISS 或其他具体存储实现。

## 7. 关键业务流

### 7.1 上传知识库文档

```text
用户选择文件
→ Qt 界面提交文件和知识库 ID
→ RAG 服务解析、切分、向量化并入库
→ RAG 服务返回处理结果
→ Qt 界面显示成功数、失败数和错误原因
```

### 7.2 知识库提问

```text
用户输入问题
→ 当前项目提交问题、知识库 ID 和会话 ID
→ RAG 服务检索相关文档块
→ RAG 服务构建 Prompt 并调用 LLM
→ RAG 服务返回最终答案和引用来源
→ 当前项目展示答案、来源和相关度
```

### 7.3 普通面试功能

```text
当前项目解析简历
→ 当前项目调用普通 LLM
→ 生成问题、评估回答或生成总结
```

该流程不经过 RAG 服务，避免把普通面试业务错误地迁入知识检索服务。

## 8. 当前实现状态

独立 RAG 服务端能力已经在 `../../rag-service` 中实现，包括文档处理、Embedding、
SQLite 向量存储、检索、Prompt、对话历史和 LLM 回答。

当前 C++/Qt 客户端已经通过统一的 `RagBackend` 接口接入远程和本地后端：

- `main_qt.cpp` 默认初始化远程 `RagClient`；设置 `use_remote_rag=false` 时初始化
  `LocalRagBackend`。
- `KnowledgeBaseWidget` 通过 HTTP 完成知识库增删、文档上传/状态查询/删除和检索测试。
- `KnowledgeChatWidget` 通过 `RagClient::Ask()` 完成连续 RAG 问答。
- `DialogSession` 通过远程检索获取面试评分参考资料。

默认 Qt 运行调用链使用独立服务；现有本地 RAG 类仅在显式回退或对比工具中使用。

## 9. 兼容范围与当前限制

- 不自动迁移旧本地数据库或知识库文件；远程知识库需要重新上传文档构建索引。
- 暂不删除现有 RAG 类和 CMake 依赖，以支持本地回退和并行对比。

## 10. 完成标准

本边界说明对应的 HTTP API 已形成：

- 人工阅读说明：`../api/rag-service-api.md`
- 机器可读契约：`../api/rag-service.openapi.yaml`

接口覆盖健康检查、知识库管理、文档上传和状态、检索测试、RAG 查询、会话清理以及统一错误响应。
